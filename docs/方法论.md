## 2. 「AI 感」从哪来，怎么去掉

AI 感很少是单一原因，通常是下面几样叠在一起：

1. **选角文字**。写「英俊」「美丽」「精致」或者只写「年轻武将」，模型会给一张网红脸。所以角色卡（`knowledge/characters/*.yaml`）写明确的年龄、体型、脸型、胡茬、疤、毛孔和老年斑，而且永远不写 young。`cinema.BANNED_WORDS` 里的词在提示词里一出现，审核就报警。
2. **皮肤和布料**。每条提示词带 `REALISM_CN`：毛孔、细纹、汗光、不均匀肤色、五官不对称，衣服有褶皱、磨损和灰。负面要求用正面说法写（「长相像普通人而不是模特」），不去点名「网红脸」，因为点名本身会把它招来。
3. **光**。AI 默认给每个人打轮廓光、蓝橙对比。画风预设（`cinema.LOOKS`）要求光来自画面里真实存在的光源（火盆、灯笼、追光），暗部保留细节，「不是每个人都打轮廓光」。
4. **动作**。慢动作和漂浮感是视频模型的通病。`MOTION_CN` 要求正常速度、有重量和惯性、会眨眼吞咽、衣服随动作摆。
5. **流程**。参考图缩到输出分辨率、存 PNG 再上传（大图会带来指纹状纹理）；不用 AI 放大器（皮肤会变蜡），要放大就用即梦「超清」放大同一条；参考图保持原色，调色只在后期做。
6. **后期**。`edit.py` 两层调色：先逐镜头测曝光、白平衡、黑位并拉齐（不同条的颜色差很多，拼起来最显假）；再整片一层胶片感：柔和的曲线、略降饱和、高光轻微泛光、细颗粒。不锐化，锐化会让皮肤更像塑料。

## 3. 镜头语言

### 运镜库（`cinema.MOVES`）

每个镜头只有一个运镜，有起幅、方向和落幅。运镜从重拍开始，在切镜头前一拍停稳（提示词里自动写「运镜从 X 秒开始，Y 秒停稳」）。

| id | 用在 | 限制 |
| --- | --- | --- |
| `whip_in` 甩镜头入 | 每段第一句 | 全片最多 4 次 |
| `push_slow` 缓推 | 任何位置 | |
| `tele_float` 长焦直播机位漂移 | 综艺语法的特写、反应 | 只用于 show |
| `handheld` 肩扛 | 双人、过肩 | 不剧烈 |
| `truck` 横移 | 中景、双人 | |
| `rack_focus` 前景转焦 | 特写、近景 | |
| `ots_drift` 过肩漂移 | 过肩 | |
| `arc_short` 30° 弧线 | 近景、双人 | 只在正脸一侧；最多 4 次（环绕用多了像 AI） |
| `low_push` 低机位仰推 | 爆点 | 最多 6 次 |
| `snap_zoom` 综艺急推 | 爆点（每四句最后一句） | 最多 5 次 |
| `crane_up` / `crane_in` 摇臂 | 开场、间奏的全景 | 唱的时候不用 |
| `pull_reveal` 拉远揭示 | 叙事插入 | 拉远会让脸变形，短用 |
| `steadicam` 稳定器倒退引导 | MV 语法的中景 | 走路会让脸变形，只用中景 |

选择规则：同一个运镜不连用（最近两个镜头里出现过就跳过），稀有运镜有全片上限，优先选用得少的。

### 镜头（`cinema.LENSES`）

show 语法近景用 85/135mm 长焦（背景压缩成光斑，就是火影有嘻哈的画面），全景用 24/35mm；mv 语法近景用 24mm 广角贴脸（Keynes vs Hayek 的画面）。

### 每四句的结构（`board.py`）

1. 第一句：唱的人独占画面，用开场运镜，转向镜头唱。
2. 中间两句：带上对手（双人 / 过肩）；其中一句的后半句切到对手的反应（长焦，嘴闭着）。
3. 第四句是爆点：用重音运镜，不靠切镜头。
4. 写了 `cutaway:` 的歌词：前半句在唱的人身上，后半句切到叙事插入，照典故字面演（破釜沉舟就真的砸锅沉船）。

开场是摇臂推向对峙，间奏是观众喊口号接下一位举麦，片尾是赢家得意、输家摇头，用近景，不拉远不走路。

## 4. 口型

1. **人声**：用 Suno 自己分出来的人声 stem（Suno 网页的 stem 分离），不用 demucs 分离整首歌。
2. **窗口**（`windows.py`）：每个生成单元的音频从第一个字前 0.3 秒开始，长度正好等于请求时长；单元以外那几句的字被静音，窗口不会在一个字中间开始或结束（在字中间开始或结束的窗口会被模型重唱）。音量统一到 −16 dBFS RMS，峰值不超过 −1 dBFS。
3. **提示词**（`prompts.py`）：音频规则放在开头，结尾再写一遍（只复制、不重唱、不加音乐）；每半句写「X.XX–X.XX 秒「……」」；嘴始终露出来，话筒拿在嘴斜下方，一手一直拿麦。
4. **单元长度**：对口型单元 4–8 秒（超过 8 秒口型开始漂），一个单元里最多两三个镜头，提示词超过 1800 字会报警（太长时模型会照着文字重唱）。
5. **测量**（`sync.py`）：每条生成回来后，用它自己的音轨和我们发出去的窗口做包络互相关，得到这一条的延迟（实测每条都不一样，−0.4 到 +0.8 秒），再用 1 秒滑窗找出跟丢的位置。剪辑按「歌曲时间 = 单元起点 + 片段时间 − 延迟」放画面，口型对不上的区间会在 EDL 里报警。
6. **人眼决定**：`aigc-mv ep pick` 记下导演选的那一条。测量结果只是参考，人眼说了算。

## 5. 剪辑

- 一句一刀，刀口在这句第一个字前 0.1 秒，0.12 秒内有拍点就吸到拍点上。
- 镜头不短于 0.8 秒（审核报警），不短于 0.5 秒（审核报错）。
- 镜头首尾相接铺满整首歌（审核检查无缝无重叠）。
- 唱的人出现在画面里的时间占主歌的 60%–90%：低于 60% 报错，高于 90% 提醒加反应镜头。
- 渲染按帧对齐：每个镜头的帧数 = round(t1×24) − round(t0×24)，不会越剪越偏。
- 没有生成素材的镜头先用首帧图按这个镜头的运镜做推拉摇移（zoompan），图也没有就放标注卡。这样花钱之前就能看完整的动态分镜。

## 6. 花钱规则（`providers/base.py`）

- 预算 = 计划生成秒数 × 单价 × 2（实际生成的秒数大约是成片用到的 2 倍）。
- 没有被 `aigc-mv ep approve` 批准过的提示词不提交；提示词一改，摘要（digest）就变，要重新批准。
- 有硬上限 `budget.cap_usd`，还有总开关 `budget.frozen`。
- 每次付费调用在 `ledger.jsonl` 记一行。
- API Key 只从环境变量读，不写进任何文件。
